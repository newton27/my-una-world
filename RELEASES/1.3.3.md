## Visitor navigation gate

The visitor gate limits guests to exactly these public paths:

- `/`
- `/login`
- `/member.php`
- `/create-account`
- `/forgot-password`
- `/terms`
- `/privacy`

A single trailing slash is tolerated on route-style paths. Logged-in members
and administrators bypass the gate completely. A blocked guest navigation
receives an HTTP 302 temporary redirect to the configured UNA root.

The feature is registered through UNA's `system / design_included` alert and
does not modify `.htaccess` or UNA core. It is a browser-navigation gate, not a
file or API security boundary. Only clear guest `GET` and `HEAD` navigations
are inspected. Dynamic, HTMX, API and XHR requests bypass it. Non-navigation
requests and ambiguous request headers also bypass it. If authentication,
request-path or redirect-root context cannot be determined safely, the gate
fails open.

Existing `system / before_install` and `system / before_uninstall` lifecycle
behavior remains registered and unchanged.

The visitor gate is enabled by default. Its checkbox is at Studio → My UNA
World → Settings:

- Checked: blocked logged-out browser navigations are redirected as described
  above.
- Unchecked: visitor gating returns immediately and all routes continue
  normally.

The setting is saved as `visitor_gate_enabled` in the existing
`.module_lifecycle_settings.json` file under the private My UNA World backup
folder. A missing file or a legacy file without this field means enabled.
Saving either state preserves the lifecycle-backup and retention values in
that file. The `system / design_included` subscription remains installed in
both states, so changing the checkbox does not alter alert registration.

## Native UNA updater

The updater source-control directory is:

`updates/1.3.2_1.3.3/`

For native UNA staging or distribution, its top-level directory must instead
be named:

`update_1.3.2_1.3.3/`

That name matches the updater `home_dir` value
`newton/my_una_world/updates/update_1.3.2_1.3.3/`; the source-control folder
name is not the native staged folder name. No updater or release archive has
been published for this candidate.

The updater adds the `system / design_included` subscription idempotently to
the existing `my_una_world_lifecycle` handler. It neither deletes nor replaces
handler rows, and it leaves the two lifecycle subscriptions untouched. Do not
manually edit `sys_modules.version`, and do not uninstall or reinstall the
module to apply the update.

The updater also runs UNA's native `update_languages` action. Its update-mode
language payload adds the Visitor Gate label and description, while the
authoritative full English language file is copied with the module source.

The payload includes the gate files and the required version metadata. In
addition to the gate implementation, `classes/MyUnaWorldRestore.php` keeps
restore registration preservation at 1.3.3 so a restore cannot write the
module registration back to 1.3.2, and `classes/MyUnaWorldStudioPage.php`
keeps Studio's displayed version synchronized at 1.3.3. These are version-only
changes; restore behavior and database-version write paths are otherwise
unchanged.

This updater is scoped to the visitor gate and required 1.3.3 version
metadata. It does not distribute every September 11 hotfix to arbitrary older
1.3.2 installations. Before deployment, compare the target installation with
the baseline tracked in [UNRELEASED.md](UNRELEASED.md), including the backup
engine and related hotfix files. Do not assume the historical 1.3.2 archive
contains those hotfixes.

## Emergency rollback during test deployment

First select the actual alert-handler id:

```sql
SELECT `id`
FROM `sys_alerts_handlers`
WHERE `name` = 'my_una_world_lifecycle';
```

Then delete only the visitor-gate subscription by resolving that handler name:

```sql
DELETE FROM `sys_alerts`
WHERE `unit` = 'system'
  AND `action` = 'design_included'
  AND `handler_id` IN (
      SELECT `id`
      FROM `sys_alerts_handlers`
      WHERE `name` = 'my_una_world_lifecycle'
  );
```

Do not delete the handler or its `before_install` and `before_uninstall`
subscriptions. From an already bootstrapped, trusted UNA context, invalidate
the alert cache with:

```php
BxDolAlerts::cacheInvalidate();
```

The verified UNA implementation calls
`BxDolDb::getInstance()->cleanCache('sys_alerts')`. Follow it with a fresh HTTP
request because in-process static alert data is not reset. A verified Studio
cache action that clears the same alert cache is also acceptable; do not use
an unverified shell or cache command.
