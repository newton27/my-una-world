## Marketplace association: separate blocked gate

The installed `sys_modules.hash` for my_una_world was empty before the update
and remained empty afterward. Site OAuth key/secret were present; their values
were never displayed. Authorized Purchases returned other products but omitted
My UNA World. The native site-key refresh `checkModules(false)` at
06:02:54 UTC returned an array of 5 products, omitted My UNA World and left its
association empty.

UNA's public client [checkModules implementation](https://github.com/unacms/UNA/blob/07b9d34f3795383c6780eae9fe9c0b505b5bf563/studio/classes/BxDolStudioInstallerUtils.php#L376)
assigns installed association hashes only from the purchased-product response.
The adjacent authorized download implementation extracts/copies the package
without assigning a hash. Downloaded packages, a functioning Info popup and a
successful native update therefore do not establish Marketplace ownership or
prove future update discovery.

| Marketplace account/site association | Both native response paths omit my_una_world; installed association remains empty | BLOCKED |
| End-to-end automatic discovery | Cannot certify while the API omits the installed product | BLOCKED |

The smallest remaining correction is an officially supported Marketplace
account/site association for this free vendor-owned product, verified by a
native response containing `name=my_una_world` and a nonempty hash. The
deployed private Market API policy is not available in the public UNA repository.
Do not manufacture an association hash, overwrite the installed module with a
full installer, or weaken integrity checks to simulate enrollment.
